一句话总则

把一个大方向、一个类目节点或一个对标 ASIN，推进到一份能发给工厂的开品 PRD。先用最便宜的闸门砍掉大部分：利润是纯算术，差评要一条条拉一条条归堆，合规最费人还可能要律师。

每一步只做一件事：第 1 步划范围、第 2 步只捞不排序、第 3 步只归类不取舍、第 5 步才砍。任何「拿不到的字段」标「待补」，绝不编数；任何示例参数显著标「示例」。

0先问清规则

没问就开跑 = 报告里全是默认值。客户端能读写本地文件时，先读 ~/.duobaoyu/selection-rules.json；有就直接用并说明「本次使用：你的规则（上次修改 X）」，没有就一次问完下面这组，问完写回该文件（含日期与一句话理由）。

问什么决定哪条门槛
哪个站点、哪个大类？已有想做的节点吗？起点宽度 —— 已有节点就跳过类目层
首批能压多少钱？首批件数、能不能做高客单
能接受的客单价区间？price_min / max；低于 $15 广告基本跑不平
做不做大件？头程报价（¥/计费kg）、什么渠道？重量上限与抛重除数 —— 最容易被忽略、最容易让整条链白做
优势在哪：自有工厂 / 设计 / 站外流量 / 资金 / 都没有？用哪套选品逻辑
新品能熬多久：3 个月回本还是能等一年？评论数门槛；要快就压到 200–500
有无食品 / 保健 / 药品资质？这些方向能否放回来
退货率能忍多少？做不做穿戴、尺码类？退货率门槛

绝对阈值（月销下限、重量上限、价格带）一次定好、全类目通用；相对阈值（单品效率倍数、均分 P30、Top3 占比排序位次）每换一个节点重算 —— 先拉该节点分布值，再定阈值。

用户在 prompt 里临时给的门槛只用这一次，不覆盖存档。

卡点：没问清就开跑，后续所有判定都建立在默认值上

1第 1 步 · 选择类目

目的是划定范围、排除不能做的，不是找机会。产出：节点白名单 + 每节点选择原因 / 推荐理由 / 受众 / 代表商品 / 销量趋势。

动作规则
逐层下钻category_tree 逐层拿节点（顶级 id 是 slug，二级以下是数字）→ 逐个 category_report
硬排除需资质的（药品、保健品、处方粮、食品接触）· 自营销售额占比过高 · 单一品牌垄断（Top3 品牌占比高 + 品牌数少）· 退货率超用户门槛；穿戴 / 尺码 / 易碎标「高退货嫌疑」留到第 6 步验证
规模下限销量、均价落在用户价格带与资金能力内
集中度只排序不排除：按 Top3 占比从低到高排取前 N。一刀切会杀掉「整体挤但某价格带没人做」的细分
趋势每个白名单节点拉近 25 个月销量趋势；最后一个月是残月，剔除再算同比：近 12 月合计 ÷ 前 12 月合计 − 1
合并读<300 评商品销量占比与同比一起读：占比高但同比在跌 = 需求退潮，不是好进
抽查类目归类有噪音，下结论前抽查榜单（实测 Dog Apparel 榜首是人用头巾）
国别每个节点都算中国卖家占比，和推荐结论一起看 —— 集中度低、趋势好但中国卖家占九成，不是好位置

白名单为 0 就放宽，每次只动一条。卖家精灵路径没有 category_tree / category_report，改用 5–10 个品类种子词 → market_research_keyword，以关键词市场代替类目节点做细分市场；集中度是点击集中度，报告里写明口径。

卡点：白名单为 0 → 放宽重跑；集中度只排序不排除

2第 2 步 · 筛选产品

把选品逻辑写成 filter，在白名单内捞商品，只捞不排序。主路径与 product_search 补充两个来源分开标注。

规则怎么算角度
A 评论门槛洼地价格带 + 月销下限 + 评论数上限 + 抛重上限时间成本
B 差评改良位月销下限 + 星级 ≤4.2产品缺陷
C 新品已验证上架 ≤12 月 + 月销下限 + 评论数上限形态验证
D 近期攒评快评论数 ÷ 在架天数，只对上架 ≤12 月的品算（老品会虚高）当下热度
E 评论转化效率月销售额 ÷ 评论数，卡评论数 ≥30（分母小会失真）评论依赖度
F FBA 占售价fba_fee ÷ price ≤18% —— 筛的是物流不吃利润的位置，不是轻小件物流拖累
J 大盘子低门槛月销售额 ≥$20k 且评论数 30–500（质量最高的一条）盘子 × 门槛

抛重 = L×W×H(cm) ÷ 抛重除数，第 2 步就挡掉大件；钢制等高密度品抛重会严重低估，第 4 步必须用 weight_g / 实重复核。

Sorftime 估毛利 gross_profit_margin 不含头程和广告，只能粗筛参考，不当硬门槛。

命中量先松后紧：>200 收紧一档、<30 放宽一档，每次只动一条并写明。

卡点：命中 >200 收紧一档、<30 放宽一档，每次只动一条并写明

3第 3 步 · 梳理产品定位

一个定位 = 节点 + 价格带 + 形态，跨两个价格带的拆成两个。形态靠标题关键词聚类；凑不够 3 款的列「散件」不硬凑。每个定位继承所属节点的竞争背景，并统计第 2 步各规则的命中分布。

打标触发条件
不推荐类目同比为负 · 或评论数中位 ≥2,000
加分评论数中位 ≤200 · 多款同时命中 ≥3 条规则 · 带内均分偏低
扣分中国卖家 ≥85% · 抛重中位 ≥3kg · 带内 <5 款

命中分布的含义：B 多 = 差评位；C / D 多 = 新品能起来；J 多 = 大盘子低门槛。

继承的竞争背景：Top3 集中度、自营占比、退货率、<300 评占比、类目同比、中国卖家占比。

这一步只归类不取舍，砍是第 5 步的事。

卡点：定位写不成一行 = 还没归好类

4第 4 步 · 拓展对标产品

每个定位 10 个：定位内头部 4 + 定位内新品 3 + 相邻价格带头部 3，按月销排序、父 ASIN 去重。

动作规则
补字段逐个 product_detail 补尺寸、实重、FBA、主图；补完当场过滤大件
补不齐标「待补」或按同规格 FBA 款代入并标推定值
入选理由每款写一句「为什么入选」，写不出的不该在这 10 个里
相邻价格带用来回答「买家凭什么多付 / 少付」，别省

Sorftime 已知坑：category_report 明细有 package_size 但没有重量、变体数、主图，这三样要 product_detail 补，一个 ASIN 一次调用 —— 要带图的 ASIN 数量开跑前规划好。

按 ASIN 拼的 Amazon 图片直链返回占位 GIF，主图只能用 product_detail.main_image。

卡点：凑不够 10 个 → 放宽价格带或并回上一个

5第 5 步 · 计算利润并筛选

货源走 1688，两路都跑、分两张表列（不能按销量混排）。

项目规则
以图搜图ali1688_product_search_from_image，用对标里形态最主流那款的主图（不是差异化最大的），一张不行换 2–3 张；捞到的多是跨境导向卖家
类目节点ali1688_category_tree 逐层到叶子 → ali1688_product_search(node_id=叶子) 只传节点；捞到的多是产业带工厂，更可能接改模
默认参数头程 ¥12/计费kg、抛重除数 6000、汇率 6.70、佣金按站点类目阶梯（不一律 15%）、广告占比 20%、退货率用节点实测值、FBA 用真值 —— 全部显著标「示例」
逆风测试采购 +10%、广告 30%、退货率 ×1.5
一组数一个定位用一组数：售价取价格带中位数，尺寸重量取 10 个对标的中位数
待补红线采购价无结果 / 报错 / 零报价都不等于零成本，标「待补」该行利润留空；相似款不是同款；不同规格不平均成一条不存在的报价
首批件数(资金上限 − 60 天广告预留 − 头程) ÷ 采购单价。广告后贡献不是净利润（未含固定管理费、税）

公式（先列给用户确认再算，尺寸为 cm，抛重直接 ÷ 除数，不要再乘 16.387）

# 单位：尺寸 cm、重量 kg、金额 USD（采购与头程运价为 CNY）
计费重       = max(实重, 抛重)
头程($/件)   = 计费重 × 运价(¥/kg) ÷ 汇率
广告前毛利   = 售价 − 佣金 − FBA − (1688 采购 ÷ 汇率 + 头程)
毛利率       = 广告前毛利 ÷ 售价
保本广告占比 = 毛利率 − 退货率
广告后贡献   = 广告前毛利 − 售价 × (广告占比 + 退货率)

判定线

判定条件动作
通过毛利率 ≥30% 且保本广告占比 ≥25%进第 6 步，回填目标售价、到岸成本上限、采购价上限、首批件数
观察毛利率 20–30%，或逆风后为负等真实报价再算
淘汰毛利率 <20%，或顺风后为负写清卡在哪项、什么条件能翻案

全部不过线时改定位或换供应链，不许调低目标利润率。

卡点：缺尺寸重量标「待补」；全不过 → 改定位或换供应链，不许调低目标利润率

6第 6 步 · 从评论找改良点

每个通过的定位挑 2 个代表 ASIN，拉差评 + customers say，必要时站外佐证。样本量必须写进报告。

归堆处理
改产品能解决进四格表，按出现次数排序
改 listing 能解决适配范围、规格说明、素材澄清
不是产品问题物流、包装破损 —— 第 1 步的「高退货嫌疑」在这里验证

改产品的每条走完四格：改良点 → 设计方向 → 规格材质 → 验收标准（可测），保留英文原话。

走不完四格的不进 PRD。与第 3 步定位冲突时以差评为准并写明改了什么。

Sorftime 接口上限：product_reviews 最多 100 条、仅近一年。

卡点：痛点全是物流类 → 无改良空间，换一条

7第 7 步 · 合规检查

无接口，检索式 + 人工核对。

检查项做法
专利先看对标标题 / 五点里自述的 "Patented"，再用改良点结构关键词 + 品牌名在 USPTO / Google Patents 检索；撞上竞品自述专利方向判高风险
商标产品名与卖点词查 USPTO；形容词性卖点词逐个查
安规按品类列必需认证，写清谁办、多久、大概多少钱

高 → 砍掉或回第 6 步；中（要办认证）→ 写进 PRD 成本与节点；低 → 通过。

报告必须出现原句：「初筛不替代法律意见，高风险必须律师复核」。

卡点：高风险 → 砍掉或回第 6 步

8第 8 步 · 产出开品文档

每个通过的定位各一份 PRD（不要只做一个）。

产出规则
PRD 八节定位 → 卖点（标对应差评条数）→ 规格（含包装尺寸与毛重上限）→ 到岸成本上限 → 验收标准 → 合规要求 → 变体规划 → 交付节点；每节标来自哪一步
打样检查表末项固定「专利核查回执，没打勾不下量产单」
5 家供应商按定位形态词先去噪，再按公式排序；十列：厂家（可点 1688 链接）· 产地 · 报价 · 起订 · 30天销量 · 复购率 · 服务分 · 发货时效 · 是否一件代发 · 在售款
降级条件候选全是 30 天销量个位数 = 这个方向没人批量做，采购价与利润结论一起降级
工厂版规格书每个定位一个文件，删掉到岸成本、售价、毛利率、保本广告占比、退货率、任何美元金额、对标 ASIN、竞品品牌名（改「市面已有品牌」）、差评条数（改「用户反馈」）；不给目标采购价，让工厂报价
工厂版必备结尾附报价要求（含税与否 · 起订量与阶梯价 · 打样费与周期 · 能否改模及费用 · 包装与外箱尺寸毛重 · 可提供的检测报告）；页脚写「本文只含规格与验收要求，不含我方成本、定价与渠道信息」
交付前自检grep 正则 B0[A-Z0-9]{8} / 到岸 / 毛利 / 差评 / $[0-9] 和竞品品牌名，结果必须为空

供应商排序分 = √(30天销量) + 复购率×0.3 + 工厂身份加分（超级工厂 30 / 实力商家 15）+ 服务分三项之和×2。

1688 价格是否含税 / 起订价未验证，报告标来源与查询日期。

卡点：花钱动作停下等人确认

附口径红线、数据源与停下点

这些规则跨步骤生效，写进每一份交付物。

A · 数据源选择（每次开跑前先查）

路径条件做法
首选 · 完整版 Sorftime客户端单独接了 Sorftime MCP类目 TOP100 category_report、商品详情 product_detail（含尺寸重量）走完整版；两条路径都能用 market_query_sorftime 里的 1688 / category_tree / potential_product
降级 · 卖家精灵没有 Sorftime 工具不要停下、也不要编数据。先把费用说明原样转告用户一次，拿到「继续」再开跑：market_research_keyword / market_mine_keywords / market_list_competitors / market_get_reviews 每次 2 积分（¥0.2），先给调用次数与积分估算，附充值链接。第 1、2 步按关键词市场圈细分；报告首节写明「数据源：卖家精灵和 Sorftime 1688，无类目 TOP100」和本轮消耗积分
控费每个 market_* 调用前按「定位数 × 对标数」这类乘法先估总次数；超预算就停下来说明再继续。返回 insufficient_balance 立即停，转告充值链接，充值后从断点继续，不要重试刷
配额Sorftime 返回「MCP使用次数已达到上限」账号级配额耗尽，立即停、别重试；告知升级或本轮剩余步骤改走卖家精灵路径（同样先告知费用）

B · 产出规范（最终交付物）

客户端能写文件时，最终交付一份自包含八 tab 单页 HTML：每步一个 tab，每个 tab = 角标 → 收敛型标题（如「87 个类目 → 9 白名单 → 2 推荐」）→ 口径行（站点 / 数据源 / 生成日期 / 样本）→ 结论先行 → KPI → 正文。

深赭 #8c3f1c + 墨棕 #2a2419，不加任何水印，禁外链 CSS / JS / 字体，图片 base64 内嵌。

第 5 步利润表必须可调：全局参数 + 每行输入，改完即时重算，带「恢复默认」。

不能写文件时按同样结构用 Markdown 分步输出；用户明确要纯文本才降级。

C · 口径红线

红线要求
不许出现没格式的段落<style> 里必须给正文 p / h3 / ul / li 设字号（12.5–13.5px）、行高（≈1.75）和段间距 —— 全局 *{margin:0} 后裸 <p> 会挤成一团；「选择原因：/ 推荐意见：/ 受众与场景：」做成带左边线的独立块；flex / grid 容器里不要直接混放文字和 <b>，先包一层 <p> 或 <span>
ASIN 表凡出现 ASIN 的表带主图与 https://www.amazon.com/dp/<ASIN> 链接；第 2 步命中结果全部逐条列出，按命中条数分组，命中原因写成一段人话
样本口径TOP100 是样本不是全量：说「进榜数」，不说「在售数」。单品平均效率 = 价格带销量占比 ÷ 价格带进榜数（1.00% 为基准）
用词说「细分市场」不说「格子」；拿不到的字段标「待补」，绝不编数；示例参数显著标「示例」；不承诺量化收益
报告内容不写 prompt、不写教学旁白
自家数据多宝鱼 MCP 只覆盖用户自己店铺数据；想看自家已有品真实表现用 data_query，与 Sorftime 市场数据分开标注来源

D · Sorftime 接口已知坑

category_search_from_top_node 的 top_node 参数失效；search_categories_broadly 的 ratings_count_max 无效且无类目参数 —— 第 1 步只走 category_tree + 逐个 category_report。

category_stats_report 的值是带前缀整句（如 "Top-80% products median price: 33.99"），先按最后一个冒号切再取数；median_price 可能是 0.00、return_rate 可能是空串，中位价用明细自算，退货率标「待补」。

集中度只有 Top3，报告里写明「Top3」，不能简写成「集中度」。占比类参数用 0–1（10% 传 0.1）；ratings_max 是星级，ratings_count_max 是评论条数。
