# 亚马逊选品开品八步 SOP

把一个大方向、一个类目节点或一个对标 ASIN，推进到一份能发给工厂的开品 PRD。

## 总则

- **顺序不能换**：成本递增 —— 利润是纯算术（最便宜）→ 差评要逐条归堆（最费人）→ 合规最贵（可能要律师）。先用便宜的闸门砍掉大部分。
- 每一步只做一件事：第 1 步划范围、第 2 步只捞不排序、第 3 步只归类不取舍、第 5 步才砍。
- 任何拿不到的字段标「待补」，绝不编数；任何示例参数显著标「示例」。
- 绝对阈值（月销下限、重量上限、价格带）一次定好全流程通用；相对阈值（效率倍数、均分 P30、Top3 位次）每换一个细分市场重算。

## 第 0 步 · 先问清规则（没问就开跑 = 全是默认值）

客户端能读写本地文件时，先读 `~/.duobaoyu/selection-rules.json`；有就直接用并告知「本次使用你的存档规则（上次修改日期）」，没有就一次问完以下 8 项并写回：

1. 站点 / 大类 / 已有节点？
2. 首批能压多少钱？
3. 客单价区间？（低于 $15 广告基本跑不平）
4. 做不做大件？头程报价（¥/计费kg）、抛重除数、汇率？
5. 优势：自有工厂 / 设计 / 站外流量 / 资金 / 都没有？
6. 新品能熬多久（回本周期）？→ 评论数门槛（要快就 200–500）
7. 有无食品 / 保健 / 药品资质？
8. 退货率能忍多少？做不做穿戴尺码类？

用户在 prompt 里临时给的门槛只用当次，不覆盖存档。

## 第 1 步 · 选类目（划范围，不是找机会）

- 逐层下钻类目节点，逐个看节点报告（销量、均价、集中度、自营占比、中国卖家占比）。
- 硬排除：需资质的品类 · 自营占比过高 · 单一品牌垄断 · 退货率超门槛；穿戴/尺码/易碎标「高退货嫌疑」留第 6 步验证。
- **集中度只排序不排除**：按 Top3 占比从低到高排取前 N。
- 趋势：拉近 25 个月销量，最后一个月是残月剔除再算同比；「<300 评商品销量占比高但同比在跌 = 需求退潮」。
- 抽查榜单防类目噪音；每个节点算中国卖家占比（≥85% 扣分）。
- 白名单为 0 → 放宽，**每次只动一条**。
- 数据源为卖家精灵（无类目 TOP100）时：用 5–10 个品类种子词跑关键词市场代替类目节点，集中度改用点击集中度，报告写明口径。

## 第 2 步 · 筛产品（只捞不排序）

在白名单内跑七套 filter，规则与公式见 `references/rules.md` §筛选规则：A 评论门槛洼地 / B 差评改良位 / C 新品已验证 / D 近期攒评快 / E 评论转化效率 / F FBA 占售价 / J 大盘子低门槛。

- 命中结果全部逐条列出、按命中条数分组、命中原因写成一段人话。
- 命中量 >200 收紧一档、<30 放宽一档，**每次只动一条并写明**。
- 抛重 = L×W×H(cm) ÷ 抛重除数，本步就挡大件；钢制等高密度品抛重低估实重，第 4 步用实重复核。
- 注意：`keyword` 参数可能被宽泛拆词匹配（如 "socket organizer" 匹配成全站 organizer），优先用精确类目节点 ID 检索。

## 第 3 步 · 梳理定位（只归类不取舍）

- 一个定位 = 节点 + 价格带 + 形态；跨两个价格带的拆成两个；形态靠标题关键词聚类；凑不够 3 款列「散件」不硬凑。
- 不推荐：类目同比为负 或 评论数中位 ≥2000。加分：评论数中位 ≤200、多款同时命中 ≥3 条规则。扣分：中国卖家 ≥85%、抛重中位 ≥3kg、带内 <5 款。
- 每个定位继承所属节点的竞争背景（Top3 集中度、自营占比、退货率、中国卖家占比等）。

## 第 4 步 · 拓展对标（补真值）

每个定位 10 个对标：定位内头部 4 + 定位内新品 3 + 相邻价格带头部 3，按月销排序、父 ASIN 去重。逐个补尺寸、实重、FBA、主图，补完当场过滤大件；补不齐标「待补」或按同规格代入并标推定值。每款写一句入选理由。

## 第 5 步 · 算利润并筛选（才砍）

完整公式、通过/观察/淘汰三档判定、1688 双路找货源（以图搜图 + 类目节点）、逆风测试，见 `references/rules.md` §利润公式与判定。

- **红线**：采购价无结果 / 零报价 ≠ 零成本，标「待补」、该行利润留空；相似款不是同款；不同规格不平均。
- 全部不过线 → 改定位或换供应链，**不许调低目标利润率**。

## 第 6 步 · 差评找改良点

每个通过定位挑 2 个代表 ASIN 拉 1–2 星评论（样本量写进报告）。归三堆：改产品能解决（走四格：改良点→设计方向→规格材质→验收标准，保留英文原话）/ 改 listing 能解决 / 不是产品问题。**走不完四格的不进 PRD。** 痛点全是物流类 = 无改良空间，换方向。

## 第 7 步 · 合规初筛

专利：先看对标标题/五点自述 "Patented"，再用改良点结构关键词 + 品牌名查 USPTO / Google Patents。商标：产品名与卖点词查 USPTO。安规：按品类列必需认证（谁办、多久、多少钱）。高风险 → 砍掉或回第 6 步。报告必须写明：**初筛不替代法律意见，高风险必须律师复核**。

## 第 8 步 · 产出开品文档

每个通过定位各一份：内部 PRD（八节，见 `references/rules.md` §交付物）+ 打样检查表 + 5 家 1688 供应商排序表 + **发工厂版规格书**（剥离成本、售价、ASIN、竞品品牌、差评字样；附报价要求）。交付前用 grep 自检敏感信息为空。

## 停下等人的三处

打样下单 · 备货 · 上架发布 —— 到这三处停住，把数字与风险摆出来等用户确认。

## 交付规范

最终交付一份自包含单页 HTML（无外链 CSS/JS/字体、图片 base64 内嵌、八 tab 结构、利润表可调可恢复默认）。**不加任何水印**；页脚写：数据源、数据截止日期、生成日期。详细规范与口径红线见 `references/rules.md` §交付规范与 §口径红线；HTML 版速查手册模板在 `assets/选品八步规则速查.html`。

## 付费数据源控费（用多宝鱼 MCP 卖家精灵路径时）

- `market_research_keyword` / `market_mine_keywords` / `market_list_competitors` / `market_get_reviews` 每次调用扣积分，先估调用次数与积分再开跑；返回 insufficient_balance 立即停并告知充值链接，从断点续跑不重试刷。
- TOP100 级产品明细按数据量计费，单次费用远高于关键词查询 —— 调用次数按「定位数 × 对标数」先估。
- 大明细（>75KB）落盘后用脚本批量解析，不塞进上下文。
